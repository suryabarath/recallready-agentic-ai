## Workflow behavior

`.github/workflows/offline-tests.yml` declares PRs targeting `main`, pushes to
`main`, and manual dispatch. The single `offline-regression` job uses standard
`ubuntu-latest` and Python 3.13, with a ten-minute timeout and cancellation of
superseded runs. Official checkout and setup-python v6 actions are pinned to
their resolved commit SHAs. The workflow checks out the PR merge candidate
using the default pull-request event; it does not use `pull_request_target`.

The job restores only the approved FDA starter ZIP, installs pinned project
dependencies, runs `pip check`, and executes the permitted pytest selection
documented in [CONTRIBUTING](../CONTRIBUTING.md). Its job summary identifies
the 21 inventory-dependent tests outside that selection. It creates no cache
or uploaded result artifact and needs no OpenAI or Qdrant credentials.

The hosted run verified dependency downloads and execution in a fresh Linux
environment. Local YAML parsing alone would not establish that result.

## Private FDA fixture

Create a repository Actions secret named `FDA_STARTER_ZIP_BASE64`, containing
the base64 encoding of the original ZIP bytes. The current 33,201-byte ZIP
encodes to 44,268 ASCII bytes, below GitHub's 48 KB secret size limit. The ZIP
is neither added to Git nor extracted. See
[Actions secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

`scripts/prepare_ci_source.py` reads the secret from its process environment,
verifies SHA-256
`b1f55e7cc2b0ec37c29b87af31478230766b3ba9b45bd0db03c8c38c1bfe2f0e`,
and exclusively creates the source at the expected sibling reference path
with mode `0600`. It accepts an existing identical file without rewriting it
and refuses to overwrite a different file. Missing/invalid input fails the
job clearly before tests, rather than skipping source validation.

The repository secret was provisioned through GitHub's public-key encryption
API; its name and creation metadata were verified without displaying its value.
The setup library was installed only in temporary tooling, with no application
dependency changes. Do not post the value in a PR or chat, print it to CI logs,
or substitute inventory/label archives. Only trusted
repository contributors should have access to the workflow and this fixture.
Fork PRs do not receive ordinary Actions secrets and will need a maintainer's
separately reviewed fixture/run arrangement; never change the trigger to
`pull_request_target` to bypass that limitation.
