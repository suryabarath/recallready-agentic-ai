## 5. Recommended call boundary

The following is a **live, potentially paid** application-code example. It
does not execute when reading this document and was not executed again for
the handoff. Use it only within an authorized pilot budget:

```python
import os
from pathlib import Path
from uuid import uuid4
from openai import OpenAI
from a1_run import run_a1_with_trace
from fda_store import FDAStore
from interpreter import Budget
from qdrant_a1 import QdrantA1

with FDAStore(Path("runtime/fda_a1.sqlite")) as store:
    retriever = QdrantA1(os.environ["QDRANT_URL"],
                         os.environ["QDRANT_API_KEY"], store)
    budget = Budget(Path("runtime/a1_usage.sqlite"))
    with OpenAI(api_key=os.environ["OPENAI_API_KEY"],
                base_url="https://api.openai.com/v1",
                max_retries=0, timeout=60) as client:
        envelope = run_a1_with_trace(
            store, retriever, client, budget,
            run_id=str(uuid4()), recall_number="H-1388-2026",
            snapshot_id=store.snapshot_id,
        )
        print(envelope.model_dump_json(indent=2))
```

The caller owns and closes the client/store and must supply a unique run ID.
Use a shared ledger for runs governed by the same accounting cap; do not
create a fresh ledger to bypass prior usage. The default local cap is $1 in
estimated charges/reservations. This is not a provider billing cutoff.

The existing CLI in `interpreter.py` runs a Group A/B interpretation pilot
with `--allow-paid-call`; it does **not** invoke the combined Qdrant service
or the trace wrapper. There is no general CLI for the latest wrapper and
no Group C paid CLI. A reusable command-line entry point remains pending.

## 6. Outcome handling for the coordinator

| Envelope field | Receiving code's responsibility |
| --- | --- |
| `run_id` | Persist as the execution identity |
| `status` | Branch on `validated` or `unresolved` |
| `result` | Preserve the entire typed result when validated |
| `error` | Record stage/code; do not automatically retry |
| `trace` | Retain evidence references, timing, attempts and accounting state |

Groups A/B return `0.1-proposed`. Group C returns
`0.2-group-c-provisional` containing `base` and `relations`; retain both.
Never flatten the relations into all possible lot/date combinations. Group C
keeps its human-review uncertainty even when validation succeeds.

Expected operational failures return unresolved envelopes. Invalid envelope
argument types and unexpected programming exceptions can propagate; handle
them at the application boundary without inventing successful facts.
The wrapper resets run-local context on exit and does not close caller-owned
resources. See [the exact envelope guide](A1_RUN_ENVELOPE_GUIDE.md).

Do not infer zero usage from missing usage or a failed ledger. A timeout may
have incurred charges. Settlement failure keeps conservative reservations.
`run_calls` links reservations to the caller's run ID in the same transaction.
Reported reasoning tokens are included in output tokens. The caller must save
the returned trace if it needs retention; durable event streaming, duplicate
run-ID enforcement and crash-complete traces are not implemented.
